**Описание:**

Смена отображаемого имени (`PUT /api/account/profile`) сразу видна другим онлайн-клиентам: панель участников открытого чата, подписи отправителя в открытой ленте (и typing), превью «последнее сообщение» в сайдбаре — без перезагрузки страницы. Права и контракт профиля не меняем — [Решения разработчика](#решения-разработчика).

**Функциональные требования:**

1. Участники: сменили имя — у остальных в открытой панели участников сразу новое имя (и инициал) — [Сценарий](#сценарий), [Frontend](#frontend).
2. Лента: в уже загруженных сообщениях открытого чата подпись отправителя обновляется; индикатор typing — тоже — [Frontend](#frontend).
3. Сайдбар: превью «Имя: текст» у строк, где этот пользователь — автор последнего сообщения, обновляется без GET списка чатов — [Frontend](#frontend).
4. Без полного reload: клиент **патчит** локальные данные по `userId`, не перечитывает участников / ленту / список чатов на каждое событие — [Frontend](#frontend).
5. Инициатор: свой профиль в меню как сейчас (`Auth.updateProfile`); чужие экраны — через событие, без `ChatChanges` ради смены имени — [Frontend](#frontend).

**Технические требования:**

1. Аудитория: **все** подключённые к хабу (broadcast), как `roomChanged` / `chatChanged` — [Realtime](#realtime).
2. Domain event **после** успешного `SaveChanges` в `ServiceAccount.UpdateProfileAsync`, только если имя реально изменилось — [События](#события).
3. Связка Security → Realtime через порт `IUserNotifyPort` (area не ссылаются друг на друга; rule-0003 п. 41): handler → порт → адаптер WebApi → `IServiceChatNotify` — [Realtime](#realtime).
4. Объекты события и payload — только через `UserMapper` в локальную переменную (rule-0003 п. 31, 44–45; [AGENTS.md](../../AGENTS.md)).
5. SignalR: клиентское событие `userChanged`; payload `userId`, `name` — [Realtime](#realtime).
6. Для патча превью в сайдбаре: поле `lastMessageSenderUserId` в `ChatListModel` и в `chatListUpdated` — [Frontend](#frontend).
7. Тесты: mapper; FE-патч участников / ленты / превью; Account регрессия; runbook realtime.

**Дополнительные сведения:**

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Кому слать | Всем подключённым к хабу (broadcast) |
| Объём | Только смена `User.Name` через профиль |
| Связка | Domain event после SaveChanges → handler → `IUserNotifyPort` → Realtime |
| Area | Событие и порт в Security; Realtime вызывается только из адаптера WebApi |
| Модель | `UserChangedEvent` (`UserId`, `Name`) |
| Payload | `userId`, `name` |
| Когда слать | Только если нормализованное имя ≠ прежнему |
| Создание объектов | Только Mapper → локальная переменная → вызов |
| FE | Патч по `userId` в ParticipantsPanel, ChatMessages (сообщения + typing), RoomChats (превью) |
| Сайдбар | Добавить `lastMessageSenderUserId` в list/notify |
| Инициатор | `Auth.updateProfile` as-is; не дергать GET ради имени |
| Права / API профиля | Не менять |

### Сценарий

1. Пользователь A меняет имя в меню аккаунта (HTTP).
2. После успешного commit в БД все онлайн-клиенты получают SignalR `userChanged`.
3. Клиенты патчат локальные имена по `userId`; полный reload участников / ленты / чатов не делается.

### As-is

```text
ServiceAccount.UpdateProfileAsync → SaveChanges → нет realtime
FE инициатор: Auth.updateProfile + ParticipantsPanel reload по currentUser.name()
Остальные: старое имя до GET / reconnect
```

### События

```text
ServiceAccount.UpdateProfileAsync
  …
  await SaveChangesAsync()
  if nameChanged:
    await Publish(UserChanged)  // realtime UI
```

### Realtime

- `IChatConnection.SendToAllAsync` → `Clients.All`
- Клиентский метод `userChanged`
- Не смешивать с `chatListUpdated` / `participant*` — отдельное событие профиля

### Frontend

- `ChatHub`: `connection.on('userChanged')` → `userChanged$`
- `ParticipantsPanel`: патч `rows[].name`; убрать reload списка из‑за смены своего имени
- `ChatMessages`: патч `senderName` у сообщений и имя в `typingUsers`
- `RoomChats`: патч `lastMessageSenderName`, где `lastMessageSenderUserId` совпал
