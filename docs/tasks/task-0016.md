**Описание:**

Индикатор «печатает…» в открытом чате: пока участник набирает текст в composer, остальные с открытым этим чатом видят, что он печатает. Без БД — только SignalR ([Realtime](#realtime)).

**Функциональные требования:**

1. Старт: при наборе непустого текста в composer остальные в группе чата видят индикатор — [Поведение](#поведение).
2. Стоп: индикатор исчезает после паузы в наборе, очистки поля, отправки сообщения или ухода из чата — [Поведение](#поведение).
3. Несколько печатающих: текст индикатора учитывает 1 / 2 / 3+ человек — [UI](#ui).
4. Себя не показывать: отправитель typing-события свой индикатор не видит.

**Технические требования:**

1. Хаб: методы клиента → сервер `StartTyping(chatId)`, `StopTyping(chatId)`; сервер → клиент `typingStarted`, `typingStopped` в группу `chat:{id}` через `OthersInGroup` — [Realtime](#realtime).
2. Доступ: только участник чата (как `JoinChat`); имя берётся на сервере (не с клиента) — [Realtime](#realtime).
3. Фронтенд: debounce/idle и refresh typing; индикатор над composer; без persistence — [Поведение](#поведение), [UI](#ui).
4. Тесты: unit/FE на hub-клиент и индикатор; docs (runbook realtime).
5. Без миграций и без REST.

**План реализации:**

1. Наполнить карточку и статус «В работе».
2. Backend: методы хаба + модель notify + `IChatMembership` для имени.
3. Frontend: `ChatHub` + логика в `chat-messages` + стили.
4. Тесты; runbook; карточка «Выполнена»; коммит.

**Дополнительные сведения:**

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Хранение | Нет (эпhemeral SignalR) |
| Группа | `chat:{chatId}` (уже из Join) |
| Имя в payload | С сервера через membership / UserPort |
| Idle → stop | ~3 с без ввода |
| Refresh пока печатает | `StartTyping` повторно ~каждые 2 с |
| Expire у получателя | ~3.5 с без нового `typingStarted` |
| Своё событие | Не показывать (`OthersInGroup` + фильтр) |

### Поведение

1. Непустой draft → `StartTyping` (если ещё не в режиме typing); таймер idle 3 с сбрасывается на каждый input.
2. Пока draft непустой и режим typing активен — раз в ~2 с повторный `StartTyping` (продление у получателей).
3. Idle 3 с / пустой draft / успешная отправка / leave чата → `StopTyping`.
4. Получатель: по `typingStarted` добавляет/обновляет пользователя; по `typingStopped` или expire — убирает.

### UI

Над composer (под лентой), muted:

| Печатают | Текст |
|----------|--------|
| 1 | `{Имя} печатает…` |
| 2 | `{Имя1} и {Имя2} печатают…` |
| 3+ | `Несколько человек печатают…` |

### Realtime

| Направление | Метод | Payload |
|-------------|--------|---------|
| Client → Hub | `StartTyping(chatId)` | — |
| Client → Hub | `StopTyping(chatId)` | — |
| Hub → Clients (others) | `typingStarted` | `{ chatId, userId, name }` |
| Hub → Clients (others) | `typingStopped` | `{ chatId, userId }` |

Не участник / без auth → `HubException` (те же тексты, что у Join).

### Вне объёма

Typing в списке чатов; «печатает» в push/уведомлениях; Redis presence.
