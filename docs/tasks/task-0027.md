**Описание:**

Вступление в чат без self-join: `RoomAdmin` (видит чат по `ChatRead`, но не участник) подаёт заявку; `ChatAdmin` принимает или отклоняет её в панели участников (бейдж на иконке). `ChatAdmin` также ищет пользователя по логину (`Search`) и добавляет сразу в участники. Права — [task-0021](task-0021.md): `ChatParticipantGrant` у `ChatAdmin`. Приглашение с Accept у приглашённого — вне этой задачи.

**Функциональные требования:**

1. Заявка: не-участник с `ChatRead` на чат подаёт заявку со stub страницы чата («Подать заявку» / «Заявка отправлена») — [Сценарий: заявка](#сценарий-заявка).
2. Панель участников у `ChatAdmin`: pending-заявки с **Принять** / **Отклонить** — [UI](#ui).
3. Бейдж на иконке «Участники»: число pending-заявок этого чата (только `ChatAdmin`), realtime — [Realtime](#realtime).
4. Добавление: `ChatAdmin` в панели ищет по логину (`Search`) и добавляет пользователя сразу в участники — [Сценарий: добавление](#сценарий-добавление).
5. Self-join убран: `POST /api/participant` только от `ChatAdmin` с `UserId` — [Решения разработчика](#решения-разработчика).
6. Дубли: один `Pending` на `(ChatId, UserId)`; уже участник / повторная заявка — отказ валидацией.
7. Каталог чатов, deep-link для чужака без `ChatRead`, invite с Accept — не делаем.

**Дополнительные сведения:**

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Discoverability | Заявка от того, кто видит чат (`RoomAdmin` / `ChatRead`); чужак по URL и каталог чатов — нет |
| Приглашение с Accept | Вне MVP; админ добавляет через `Participant.Create` + `Search` |
| Кто создаёт участника | Сервис: Accept или Create → `CreateStageAsync` в той же UoW |
| Self-join | Убрать |
| Сущность | Одна: `JoinRequest` (без Invitation) |
| UI заявок | В панели участников + бейдж на иконке |
| Поиск | `User.SearchAsync` по логину |
| Имена | `JoinRequestCreateRequest`, `AcceptAsync`, `RejectAsync`, `DisplayPendingListPageAsync`; `ParticipantCreateRequest { ChatId, UserId }`; `UserSearchRequest` |
| Expiry / rate limit / аудит | Не в этой задаче |

### Сценарий: заявка

1. `RoomAdmin` открывает чат комнаты, в котором не участник → stub «Подать заявку».
2. `JoinRequest.CreateAsync` → `Pending`.
3. У `ChatAdmin` бейдж и строка заявки в панели; **Принять** → участник + роли; **Отклонить** → `Rejected`.
4. Заявитель видит «Заявка отправлена» / после Accept — ленту как участник.

### Сценарий: добавление

1. `ChatAdmin` в панели вводит логин → `User.SearchAsync`.
2. **Добавить** → `Participant.CreateAsync({ ChatId, UserId })` → сразу участник + `participantJoined`.
