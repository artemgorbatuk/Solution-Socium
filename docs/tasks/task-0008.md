**Описание:**

Добавить сообщения (Message): таблица `Messages` в БД Socium со связью «один ко многим» с чатами — в чате может быть много сообщений, сообщение принадлежит ровно одному чату. Сделать CRUD сообщений на бекенде по образцу Chat и оживить окно чата: отправка, список, изменение и удаление сообщений.

**Функциональные требования:**

1. База данных: таблица `Messages`, каждое сообщение ссылается на свой чат; при удалении чата (и комнаты) его сообщения удаляются вместе с ним без отдельного предупреждения — состав полей в [Состав полей Message](#состав-полей-message).
2. Длина текста: не ограничена приложением — колонка `text`; фактический предел — размер запроса сервера (по умолчанию Kestrel ~30 МБ).
3. CRUD сообщений: список сообщений чата, карточка, создание, изменение текста и удаление через API `api/message` плюс данные для форм — набор в [Эндпоинты API](#эндпоинты-api).
4. Перенос сообщения: не поддерживается — чат задаётся при создании, изменение меняет только текст; время создания при изменении не меняется.
5. Окно чата: сообщения по времени создания, новые внизу; отправка из поля ввода — Enter, новая строка — Shift+Enter; у сообщения меню «…» с пунктами «Изменить» и «Удалить» — поведение в [Сообщения в окне чата](#сообщения-в-окне-чата).

**Технические требования:**

1. Структура: библиотеки, файлы, именование и слои — по [rule-0003](../rules/rule-0003-backend.md), по образцу цепочки Chat (task-0006).
2. Связь: описана со стороны `Message` — `HasOne(Chat)` → `WithMany(Messages)`, `HasForeignKey(ChatId)`, `OnDelete(Cascade)`; индекс `IX_Messages_ChatId_CreatedAt` под выборку сообщений чата по времени.
3. Текст: колонка `text` без `HasMaxLength` — исключение п. 12 rule-0003 «по решению задачи»; при сохранении текст обрезается по краям, переносы строк внутри сохраняются.
4. Время создания: `CreatedAt` (`timestamp with time zone`, UTC) задаёт сервис через `TimeProvider` (в DI — `TimeProvider.System`), чтобы время можно было подменить в тестах.
5. Миграция: одна миграция `Task0008`, накатывается при старте WebApi в окружении `Development`.
6. Выборка: критерии — через `MessageQueryOptions` (`ChatId`); список — по `CreatedAt`, затем по `Id`; весь список чата без постраничной загрузки.
7. Проверки сообщения: primary (запрос, пустые `Id` / `ChatId`) → accessibility (сообщение или чат найдены) → domain (текст не пустой).
8. Тесты: по [rule-0004](../rules/rule-0004-tests.md) — unit, интеграционные тесты сервиса и API (включая текст в 1 000 000 символов и каскадное удаление), фронтенд-тесты и E2E.
9. Фронтенд: сообщения — в `app/messages/` (клиент API, модели, лента с полем ввода, строка сообщения, окно удаления); стили — только токены rule-0005.

**Дополнительные сведения:**

### Состав полей Message

| Поле      | Тип        | Обязательное | Ограничения                                                          |
|-----------|------------|--------------|----------------------------------------------------------------------|
| Id        | `Guid`     | Да           | Первичный ключ, `Guid` v7                                            |
| ChatId    | `Guid`     | Да           | Внешний ключ на `Chats.Id`, `ON DELETE CASCADE`                      |
| Text      | `string`   | Да           | `text` без ограничения длины, не пустой                              |
| CreatedAt | `DateTime` | Да           | `timestamp with time zone`, UTC, задаётся при создании и не меняется |

Навигация: `Message.Chat` и `Chat.Messages`. Индекс `IX_Messages_ChatId_CreatedAt`.

### Эндпоинты API

Набор по rule-0003 (п. 37), как у `ChatController`.

| Метод    | Маршрут               | Действие        | Метод сервиса            | Запрос / ответ                                          |
|----------|-----------------------|-----------------|--------------------------|---------------------------------------------------------|
| `GET`    | `/api/message`        | `List`          | `DisplayListPageAsync`   | `MessageListPageRequest` (`chatId`) / `MessageListPageResponse` |
| `GET`    | `/api/message/info`   | `Info`          | `DisplayInfoPageAsync`   | `MessageInfoPageRequest` / `MessageInfoPageResponse`    |
| `GET`    | `/api/message/create` | `Create`        | `DisplayCreatePageAsync` | `MessageCreatePageRequest` (`chatId`) / `MessageCreatePageResponse` |
| `POST`   | `/api/message`        | `Create`        | `CreateAsync`            | `MessageCreateRequest` (`chatId`, `text`) / `MessageCreatePageResponse` |
| `GET`    | `/api/message/update` | `Update`        | `DisplayUpdatePageAsync` | `MessageUpdatePageRequest` / `MessageUpdatePageResponse` |
| `PUT`    | `/api/message`        | `Update`        | `UpdateAsync`            | `MessageUpdateRequest` (`id`, `text`) / `MessageUpdatePageResponse` |
| `GET`    | `/api/message/delete` | `DeleteConfirm` | `DisplayDeletePageAsync` | `MessageDeletePageRequest` / `MessageDeletePageResponse` |
| `DELETE` | `/api/message`        | `Delete`        | `DeleteAsync`            | `MessageDeleteRequest` / `MessageDeleteResponse`        |

Неизвестный чат в списке и при создании — `404`, пустой `chatId` — `400`, пустой текст — `422`.

### Сообщения в окне чата

| Блок            | Поведение                                                                                      |
|-----------------|------------------------------------------------------------------------------------------------|
| Лента           | Сообщения по времени, новые внизу; при открытии чата и после отправки лента прокручивается вниз; пустой чат — «Сообщений пока нет» |
| Сообщение       | Сообщения отправителя прижаты вправо (пока нет пользователей, все сообщения — свои), ширина всегда 55% колонки; фон отправителя `--sc-message-sender-bg`; текст с сохранёнными переносами строк, длинные слова переносятся; время — «15:02» за сегодня, иначе дата и время; полная дата — во всплывающей подсказке |
| Отправка        | Enter или кнопка «Отправить» — `POST /api/message`; Shift+Enter — новая строка; кнопка активна, когда текст не пустой; после отправки поле очищается; ошибка — над полем ввода |
| Меню сообщения  | Кнопка «…» при наведении, как у чата; пункты «Изменить» и «Удалить»                            |
| Изменение       | На месте сообщения: многострочное поле, Enter или «Сохранить» — `PUT /api/message`, Shift+Enter — новая строка, Esc или «Отмена» — закрыть; без изменений запрос не отправляется |
| Удаление        | Окно подтверждения «Удалить сообщение?» с началом текста, «Удалить» — `DELETE /api/message`     |
| Смена чата      | Набранный текст сбрасывается, лента загружается заново                                         |
