**Описание:**

Регистрация с подтверждением email и сброс пароля поверх входа из [task-0011](task-0011.md). Регистрация — email, логин, имя и пароль; вход по-прежнему по логину и паролю. Каналы писем — `Messaging/Services.Messaging`; одноразовые токены — та же область `Messaging` со своим контекстом БД, по тому же принципу, что `Security`. Граница сознательная: письма и токены не привязаны к Security, чтобы позже слать уведомления не про логин (приглашения, события чата и т.п.) без раздувания области входа.

**Функциональные требования:**

1. Регистрация: поля email, логин, имя и пароль; после успешной регистрации пользователь **не** входит — экран «Проверьте почту» — макет в [Экраны](#экраны).
2. Подтверждение: письмо со ссылкой; по ссылке email подтверждается; до подтверждения вход запрещён — отказ без подсказки, подтверждён ли email или неверный пароль (тот же стиль, что «Неверный логин или пароль»).
3. Повторная отправка: «Выслать письмо ещё раз» на экране «Проверьте почту» и на экране входа; ограничение частоты отдельной политикой для писем; ответ не раскрывает, существует ли email.
4. Вход: без изменений по смыслу task-0011 — логин, пароль, «Запомнить меня»; идентификатор входа — логин, не email.
5. Сброс пароля: «Забыли пароль?» на экране входа — ввод email → письмо со ссылкой → страница нового пароля; после смены все refresh-токены пользователя отзываются; ответ на запрос письма не раскрывает, есть ли такой email.
6. Профиль: имя как сейчас; email показывается (только чтение в этой задаче); смены email нет.
7. Пароль: правила длины как в task-0011 (8–128).
8. Локальная разработка: SMTP-ловушка **Mailpit** в `deploy/development/docker-compose.yml` (как в «Автокласс Отчёты»), без внешнего сервиса — детали в [Почта](#почта).

**Технические требования:**

1. Раскладка проектов — в [Структура](#структура): в папке `Messaging/` — `Services.Messaging` (SMTP, каналы, тексты, без БД) и токены писем со своим `DbContextMessaging`.
2. Пользователь (Security): в `User` — `Email` (уникальный, нормализованный), `IsEmailConfirmed`; логин — уникальный идентификатор входа; refresh-токены без изменений.
3. Токены писем (Messaging): таблица `EmailTokens` — `UserId` без FK и навигации на `User` (как `Participant.UserId`), тип (подтверждение / сброс), хеш SHA-256, срок, время использования; plain-токен только в письме; время через `TimeProvider` — [Модели](#модели).
4. Связь областей: проекты `Security` не ссылаются на `Messaging`; Security вызывает порт `IEmailPort` в `Services.Security/Ports/`, адаптер в `WebApi/Ports/` вызывает сервис области Messaging (зеркально `IUserPort`).
5. Миграции: `Task0012` в Security (`Email`, `IsEmailConfirmed`) и `Task0012` в Messaging (`EmailTokens`); порядок при старте — Socium → Security → Messaging. Локально пользователей без email сейчас нет; в тестах пользователи создаются с подтверждённым email.
6. Сценарии: регистрация создаёт пользователя с `IsEmailConfirmed = false` и через порт выдаёт токен + письмо; вход проверяет подтверждение; подтверждение, повторная отправка и сброс — `api/account` (не CRUD); сброс пароля после проверки токена меняет хеш и отзывает refresh в Security.
7. Ограничение частоты: вход и регистрация — политика `auth` (как в task-0011); повторная отправка подтверждения и запрос сброса пароля — отдельная политика для писем (свой лимит в настройках).
8. Фронтенд: форма регистрации с email; экран «Проверьте почту»; маршрут подтверждения по токену; «Забыли пароль?» и страница нового пароля; после успешного подтверждения — экран входа с сообщением вроде «Почта подтверждена, войдите» (без автологина).
9. Тесты: unit каналов и валидаторов; интеграционные — регистрация без входа, вход до/после подтверждения, повторная отправка, сброс и отзыв refresh; E2E — регистрация → письмо (заглушка канала) → подтверждение → вход; сброс пароля. SMTP в тестах не используется.
10. Документы: rule-0003 — область `Messaging` (`Services.Messaging` + Tokens), порт `IEmailPort`; runbook — Mailpit и секция `Messaging`.

### Структура

```text
src/backend/SociumApp/
  Messaging/                       # область писем
    Services.Messaging/            # SMTP, каналы, тексты — без БД
    Datasource.Messaging.Ef/       # EmailTokens, DbContextMessaging,
                                   # __EFMigrationsHistory_Messaging
    Repositories.Messaging.Ef/
    Services.Messaging.Tokens/     # выдача/проверка токена, отправка через IMessageContext
                                   # (имя .Tokens — чтобы не совпасть с Services.Messaging)
  Security/                        # User.Email, IsEmailConfirmed; IEmailPort в Ports/
  WebApi/Ports/                    # адаптер IEmailPort → Services.Messaging.Tokens
```

БД та же — `Socium`. `UserId` в `EmailTokens` без внешнего ключа на `Users`.

### Почта

Локально — **Mailpit** (`axllent/mailpit:latest`), как `reports-dev-mailpit` в Автоклассе. Добавить в `deploy/development/docker-compose.yml` рядом с Postgres:

| Порт | Назначение |
|------|------------|
| `1025` | SMTP — WebApi на хосте шлёт сюда (`Messaging:Smtp` → `localhost:1025`) |
| `8025` | UI писем — http://localhost:8025 |

Контейнер: `socium-dev-mailpit`. `start-solution.ps1` поднимает compose целиком — Mailpit стартует вместе с Postgres.

| Окружение | Как |
|-----------|-----|
| Development | Mailpit; From — `noreply@localhost`; BaseUrl ссылок — `http://127.0.0.1:4200/...` |
| Testing | Канал-заглушка в DI: письма не уходят, токен доступен тесту |
| Production | SMTP из конфигурации / секретов; пароль SMTP не в репозитории |

Срок токена подтверждения и сброса — в `MessagingOptions` (ориентир эталона: подтверждение 2 дня, сброс 1 день).

### Эталон Messaging

Образец каналов — `autoclass-reports.ru/src/backend/ReportsApp/Services.Messaging`.

Берётся:

- `IMessageChannel` / `SmtpEmailChannel`, `IMessageContext`, `MessagingOptions` (SMTP, BaseUrl ссылок);
- тексты писем подтверждения и сброса;
- идея токена: 64 случайных байта, в хранилище только SHA-256.

Отличается:

| Эталон | Socium |
|--------|--------|
| Токен на DTO / полях пользователя | Область `Messaging`, таблица `EmailTokens` |
| Один проект Messaging без БД | В `Messaging/`: `Services.Messaging` (каналы) + Datasource/Tokens |
| `DateTimeOffset.UtcNow` | `TimeProvider` |
| Security знает SMTP напрямую | Security → `IEmailPort` → адаптер → область Messaging → каналы |
