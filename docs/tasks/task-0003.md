**Описание:**

Создать цепочку библиотек бекенда `Datasource.Socium.Ef` → `Repositories.Socium.Ef` → `Services.Socium`, через которую WebApi выполняет CRUD-операции с комнатами (Room). Данные хранятся в базе данных Socium в таблице Rooms. Структура повторяет эталон `autoclass-reports.ru/src/backend/ReportsApp/Reports` с улучшениями, зафиксированными в [rule-0003](../rules/rule-0003-backend.md). Во фронтенде комнаты выводятся в боковой панели приложения.

**Функциональные требования:**

1. База данных: создана БД `Socium` с таблицей `Rooms` — хранение комнат; состав полей — в [Состав полей Room](#состав-полей-room).
2. CRUD комнат: список, карточка комнаты, создание, изменение и удаление через API `api/room`, плюс данные для форм создания, изменения и подтверждения удаления — набор эндпоинтов в [Эндпоинты API](#эндпоинты-api).
3. Исход операции: каждый ответ содержит тип и текст сообщения для пользователя; ошибки возвращаются как Problem Details с кодом по типу ошибки — соответствие в [Коды ответов](#коды-ответов).
4. Боковая панель: слева на каждой странице фронтенда — список комнат, поиск по названию, создание, переименование и удаление комнаты, сворачивание и изменение ширины панели, место под профиль пользователя — состав в [Боковая панель](#боковая-панель).

**Технические требования:**

1. Структура: библиотеки, папки, файлы, именование и правила слоёв — по [rule-0003](../rules/rule-0003-backend.md); инвентаризация файлов и их аналогов в эталоне — в [Структура библиотек](#структура-библиотек).
2. Расположение: area-библиотеки — в `src/backend/SociumApp/Socium/`, общая библиотека — в `src/backend/SociumApp/Services.Shared/`; в `Solution-Socium.slnx` area-проекты лежат в папке решения `/Socium/`.
3. Стек данных: PostgreSQL, EF Core 10 (`Microsoft.EntityFrameworkCore`, `.Relational`, `Npgsql.EntityFrameworkCore.PostgreSQL`); пакеты `Design` и `Tools` — только в `WebApi`.
4. Локальная БД: собственный PostgreSQL проекта в Docker, описан в `deploy/development/docker-compose.yml`, порт на хосте `5433`; БД `Socium` создаётся при старте контейнера, таблицы — миграцией — подробности в [Решения](#решения).
5. Строка подключения: `ConnectionStrings:Socium` в `WebApi/appsettings.Development.json` — согласованное исключение rule-0003 для локальной разработки.
6. Миграция: одна миграция `Task0003`, накатывается при старте WebApi в окружении `Development`.
7. Объём: в задачу не входит то, чего нет в CRUD комнат — список в [Что не переносится](#что-не-переносится).
8. Фронтенд панели: Angular standalone-компонент на сигналах, свой CSS без UI-библиотек; тема оформления не делается — она будет отдельной задачей; данные — через существующие эндпоинты `GET /api/room`, `POST /api/room`, `PUT /api/room`, `GET /api/room/delete` и `DELETE /api/room`.

### Эндпоинты API

Набор по rule-0003 (п. 37), повторяет CRUD `SaleController` / `IServiceSale`. Маршрут контроллера — `api/[controller]`: на префикс `/api` настроен прокси фронтенда (task-0002).

| Метод    | Маршрут            | Действие контроллера | Метод сервиса            | Запрос / ответ                                     |
|----------|--------------------|----------------------|--------------------------|----------------------------------------------------|
| `GET`    | `/api/room`        | `List`               | `DisplayListPageAsync`   | `RoomListPageRequest` / `RoomListPageResponse`     |
| `GET`    | `/api/room/info`   | `Info`               | `DisplayInfoPageAsync`   | `RoomInfoPageRequest` / `RoomInfoPageResponse`     |

| `GET`    | `/api/room/update` | `Update`             | `DisplayUpdatePageAsync` | `RoomUpdatePageRequest` / `RoomUpdatePageResponse` |
| `PUT`    | `/api/room`        | `Update`             | `UpdateAsync`            | `RoomUpdateRequest` / `RoomUpdatePageResponse`     |

| `DELETE` | `/api/room`        | `Delete`             | `DeleteAsync`            | `RoomDeleteRequest` / `RoomDeleteResponse`         |

### Коды ответов

Сервис задаёт тип сообщения (`MessageType`), `ApiControllerBase.FromResponse` переводит его в HTTP-ответ (rule-0003, п. 38).

| `MessageType`                 | HTTP  | Тело                    |
|-------------------------------|-------|-------------------------|
| `LOADED`, `SAVED`, `WARNING`  | `200` | `ApiSuccessResponse<T>` |
| `BAD_REQUEST`                 | `400` | Problem Details         |
| `NOT_FOUND`                   | `404` | Problem Details         |
| `INVALID`                     | `422` | Problem Details         |
| `ERROR`                       | `500` | Problem Details         |

Модель ответа (`MessageType`, `MessageInfo`, `ResponseInfo`, `ApiControllerBase`, `ApiSuccessResponse`, `ApiProblem`) переносится из эталона без изменений, включая поля оформления: на них опираются flash-сообщения фронтенда эталона.

### Боковая панель

Компонент `Sidebar` (`src/frontend/SociumWeb/src/app/layout/sidebar/`), сверху вниз:

| Блок            | Поведение                                                                                         |
|-----------------|---------------------------------------------------------------------------------------------------|
| Заголовок       | Название «Socium» и кнопка сворачивания; в свёрнутом виде остаётся только кнопка разворота        |
| Новая комната   | Кнопка открывает поле названия; «Создать» или Enter — `POST /api/room`, Esc или «Отмена» — закрыть; при ошибке под полем выводится `detail` из Problem Details |
| Поиск           | Фильтр загруженного списка по вхождению в название без учёта регистра, на клиенте                 |
| Комнаты         | Список из `GET /api/room` (сортировка — на сервере, по названию); состояния «Загрузка…», «Комнат пока нет», «Ничего не найдено», ошибка загрузки |
| Меню комнаты    | Кнопка «…» появляется при наведении или фокусе (на сенсорных экранах видна всегда); пункты «Переименовать» и «Удалить»; закрывается щелчком вне меню и Esc |
| Переименование  | Название правится на месте строки: «Сохранить» или Enter — `PUT /api/room` с обрезанным названием, Esc или «Отмена» — закрыть; без изменений запрос не отправляется; ошибка сервера выводится под полем; после сохранения список перезагружается |
| Удаление        | Окно подтверждения (`RoomDeleteDialog`): название берётся из `GET /api/room/delete`, «Удалить» — `DELETE /api/room`; закрывается «Отмена», Esc и щелчком по фону; если комнаты уже нет, выводится ответ `404` и удаление недоступно |
| Профиль         | Заглушка «Гость» — до появления авторизации                                                       |
| Ширина          | Правый край панели перетаскивается мышью или меняется клавишами ←/→ (шаг 16 px), Home/End — минимум/максимум; минимум 200 px, максимум — половина окна, по умолчанию 260 px; при сужении окна панель ужимается до половины, а при расширении возвращается к выбранной ширине; ширина сохраняется в `localStorage` (`socium.sidebar.width`), двойной щелчок по краю сбрасывает её |

Сама строка комнаты пока не открывает страницу: страницы комнаты ещё нет. Группировка по датам, как в образце, не делается — у `Room` нет дат.

Эти части эталона не нужны для CRUD комнат:

- папки `Seeds/`, `Rules/`, `Calculators/`, `Cache/`, `Workers/` и прочие папки отчётной логики;
- авторизация: атрибуты `[Authorize]` и `AuthenticationRegistration` (метод `TryGetUserId` остаётся в `ApiControllerBase`, так как модель ответа переносится без изменений);
- `UserExceptionHandler`, `ApplicationPipeline`, `SecurityStartupDiagnostics`;
- файлы `appsettings` для окружений, кроме `Development`.

### Отличия от эталона

Улучшения, зафиксированные в rule-0003 относительно кода и правила эталона:

| Тема                     | Эталон                                                                  | Socium (rule-0003)                                                   |
|--------------------------|-------------------------------------------------------------------------|----------------------------------------------------------------------|
| Генерация ключа          | Правило требует `ValueGeneratedNever()`, код — `GuidV7ValueGenerator`   | Только `GuidV7ValueGenerator` (п. 10)                                |
| Фильтры выборки          | Правило — `{Entity}QueryOptions`, код — `{Entity}Options`               | `{Entity}QueryOptions` (п. 6, 19)                                    |
| Имя сущности             | Встречается множественное число (`Sales`)                               | Сущность в единственном числе: `Room` (п. 6)                         |
| Design-time factory      | Строка подключения зашита через `#if DEBUG`; factory зарегистрирована в DI | Строка из `ConnectionStrings__Socium`, в DI не регистрируется (п. 8) |
| Порядок валидации        | Правило — primary → domain → accessibility, код — primary → accessibility → domain | primary → accessibility → domain с кодами ответов (п. 27) |
| Ответ на ошибку запроса  | `ServiceReportPreset` вызывает `ResponseInfo.Invalid` с `BAD_REQUEST`: фабрика бросает исключение, клиент получает `500` | `ResponseInfo.BadRequest` с `BAD_REQUEST`, метод и тип всегда совпадают (п. 27) |
| Трекинг                  | Не описан                                                               | Списки — `AsNoTracking`, одиночное чтение — с трекингом (п. 20)     |
| Миграции при старте      | Правило — только `Demo`, код — `Demo` и `Development`                   | Только `Development` (п. 16)                                         |
