**Описание:**

Вложения к сообщениям чата: картинки и файлы. Байты лежат на диске, метаданные и Guid — в отдельной области `Files` со своим `DbContext`, по тому же принципу границы, что `Messaging` в [task-0012](task-0012.md). Область `Socium` не знает про HDD и не хранит содержимое файлов — только ссылки на `fileId` через порт.

**Функциональные требования:**

1. Отправка: у поля сообщения — выбор файла (скрепка); можно отправить текст, файл или оба; лимиты размера и типов — в [Лимиты](#лимиты).
2. Лента: картинки (`image/jpeg`, `image/png`, `image/webp`, `image/gif`) — превью inline; остальные типы — имя файла и скачивание.
3. Скачивание: участник чата открывает/скачивает вложение своего сообщения или чужого в том же чате; посторонний — отказ.
4. Удаление сообщения: связанные файлы удаляются с диска и из метаданных (или помечаются удалёнными с последующей очисткой — решение в реализации, предпочтение удалить сразу в первой версии).
5. Редактирование текста сообщения: вложения не меняются в этой задаче (нельзя заменить/добавить файл после отправки).
6. Локальная разработка: корень хранения на HDD из конфига; каталог рядом с деплоем / volume — [Хранение](#хранение).

**Технические требования:**

1. Раскладка — в [Структура](#структура): библиотека `Services.Files` (`IFileStore`, локальная реализация) и область `Files/` (Datasource → Repositories → Services) со своим контекстом.
2. Метаданные: таблица `Files` (или `StoredFiles`) — Id Guid v7, исходное имя, ContentType, Size, StorageKey (относительный), UploadedByUserId, CreatedAt; привязка к сообщению — `OwnerType` + `OwnerId` без FK на `Messages` (как `EmailTokens.UserId`) — [Модели](#модели).
3. Диск: байты по пути `RootPath` + `StorageKey`; в БД абсолютных путей нет.
4. Связь областей: `Socium` не ссылается на `Files`; порт `IFilePort` в `Services.Socium/Ports/`, адаптер в `WebApi/Ports/`.
5. Миграции: `Task0013` в Files; при необходимости правка Socium (поля сообщения / список fileId в контракте); порядок при старте — Socium → Security → Messaging → Files.
6. API: загрузка файла (`POST` multipart), скачивание через уже существующий `IFileDownload` в Shared; создание сообщения принимает текст и/или список `fileId`.
7. Конфиг: секция `Files` (`RootPath`, MaxBytes, AllowedContentTypes) в appsettings; Development — путь из [Хранение](#хранение).
8. Фронтенд: кнопка вложения у поля ввода, превью перед отправкой, отображение в ленте.
9. Тесты: unit store (temp-каталог); integration загрузка/скачивание/удаление с сообщением; E2E — отправить картинку в чат и увидеть превью. В тестах — отдельный temp `RootPath`, не общий каталог разработчика.
10. Документы: rule-0003 — область `Files`, `Services.Files`, порт `IFilePort`; runbook — каталог файлов и секция `Files`.

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Карточка | Новая 0013 |
| Граница | Как Messaging: отдельная area + библиотека store, не метаданные в Socium |
| БД | Свой `DbContextFiles`, таблицы в БД `Socium` |
| Байты | HDD / volume, не BLOB в Postgres |
| Ключ на диске | Относительный (`StorageKey`); корень — `Files:RootPath` |
| Эталон путей | В Автоклассе отдельного file-store нет; ориентир — volume логов `/app/logs` в compose |
| Связь с Message | `OwnerType`/`OwnerId` без FK |
| Socium ↔ Files | Порт `IFilePort` + адаптер WebApi |
| Первая версия | Картинки + произвольные файлы в лимитах; без замены вложений при edit |
| S3 / CDN | Не в этой задаче; `IFileStore` позволит заменить реализацию позже |

### Структура

```text
src/backend/SociumApp/
  Files/
    Services.Files/                # IFileStore, LocalFileStore, Options — без БД
    Datasource.Files.Ef/           # StoredFile, DbContextFiles,
                                   # __EFMigrationsHistory_Files
    Repositories.Files.Ef/
    Services.Files.Stored/            # сервис area (суффикс .Stored — имя Services.Files занято)
  Socium/                          # сообщение + fileId через IFilePort
  WebApi/Ports/                    # FilePort, MessageFileOwnerAccess
```

### Модели

```csharp
// Datasource.Files.Ef
public enum FileOwnerType
{
    Message = 0,
}

public class StoredFile
{
    public required Guid Id { get; set; }
    public required string OriginalFileName { get; set; }
    public required string ContentType { get; set; }
    public required long SizeBytes { get; set; }
    public required string StorageKey { get; set; }
    public required Guid UploadedByUserId { get; set; }
    public required DateTime CreatedAt { get; set; }
    public FileOwnerType? OwnerType { get; set; }
    public Guid? OwnerId { get; set; }
}
```

Контракт сообщения дополняется коллекцией вложений (id, имя, contentType, size, url/id для скачивания) — детали в реализации.

### Хранение

| Окружение | RootPath (ориентир) |
|-----------|---------------------|
| Development (WebApi на хосте) | каталог в репозитории, напр. `data/files` (в `.gitignore`) или явный путь в `appsettings.Development.json` |
| Docker (когда backend в compose) | volume `socium-volume-dev-files` → `/app/files`, как `…-backend-logs` → `/app/logs` в Автоклассе |
| Testing | уникальный temp-каталог на фикстуру |

Файл на диске: `{RootPath}/{StorageKey}`; `StorageKey` — например `{guid:N}` или `{guid:N}{ext}`.

### Лимиты

Ориентир для первой версии (уточняется в Options):

| Параметр | Значение |
|----------|----------|
| MaxBytes одного файла | 5 MiB |
| Вложений на сообщение | 1…5 |
| Типы | картинки, PDF, Office, код/текст (см. `Files:AllowedContentTypes` и категории UI) |

### Удаление сообщения и файлов

Сейчас: сначала файлы (диск + `StoredFiles`), потом сообщение. Общего отката нет — разные `DbContext` и диск не в одной транзакции. При обрыве посередине возможны сироты или сообщение без вложений. Оставляем так.

Атомарность двух БД + диск (saga / outbox) — отдельная задача, не в объёме 0013.

### Вне объёма

Realtime (SignalR), вирус-скан, серверный resize/thumbnail pipeline, S3, голосовые сообщения, замена вложений при редактировании текста, saga/outbox для согласованного удаления файлов и сообщения.
