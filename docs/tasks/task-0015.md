**Описание:**

Realtime для списка чатов в комнате: без F5 обновляются превью последнего сообщения и счётчик непрочитанных; чаты с новой активностью и только что созданные — сверху. Статусы доставки/прочтения — на `Recipient` в БД Socium ([Хранение прочитанного](#хранение-прочитанного)).

**Функциональные требования:**

1. Превью: в строке списка чата видно последнее сообщение (текст усечённый или пометка о вложении) и при необходимости имя отправителя — [Превью](#превью).
2. Непрочитанные: у участника виден счётчик сообщений без `MessageRead`; свои сообщения не входят в счётчик; при прочтении в окне чата — выставляется `MessageRead` — [Хранение прочитанного](#хранение-прочитанного).
3. Доставка в окно: когда сообщение попало в ленту получателя (открытый чат / realtime), выставляется `MessageDelivered` — [Хранение прочитанного](#хранение-прочитанного).
4. Realtime списка: при новом / изменённом / удалённом последнем сообщении строки списка у других обновляются без перезагрузки — [Realtime](#realtime).
5. Сортировка: чаты с более новым последним сообщением выше; новый чат без сообщений — сверху — [Сортировка](#сортировка).

**Технические требования:**

1. Миграция Socium `Task0015`: на `Recipient` поля `MessageSent`, `MessageDelivered?`, `MessageRead?`; без `MessageDeleted` (сообщения удаляются насовсем) — [Хранение прочитанного](#хранение-прочитанного).
2. При создании сообщения: для каждого recipient — `MessageSent = now`; индексы под unread-запросы (UserId + MessageRead / связь с Chat).
3. Список чатов REST: расширить `ChatListModel` превью и `unreadCount` (`MessageRead IS NULL` у текущего пользователя в чате); сортировка по активности.
4. Mark delivered / read: API или side-effect с фронта / при отображении в ленте — [Хранение прочитанного](#хранение-прочитанного).
5. Realtime: группа `user:{userId}` (рядом с `chat:{chatId}` из [task-0014](task-0014.md)); событие списка участникам; `IChatConnection.SendToUser(s)`.
6. Фронтенд: превью и бейдж; join user-группы; патч списка; вызовы delivered/read по правилам ниже.
7. Тесты: list (превью, сортировка, unread); sent/delivered/read; notify списка.
8. Документы: rule-0003 при необходимости; runbook; карточка. Redis / область `Caching` — **не в этой задаче**.

### Хранение прочитанного

Расширение существующей сущности (сейчас Id, MessageId, UserId):

```csharp
public class Recipient
{
    public required Guid Id { get; set; }
    public required Guid MessageId { get; set; }
    public Guid? UserId { get; set; }

    public DateTime MessageSent { get; set; }
    public DateTime? MessageDelivered { get; set; }
    public DateTime? MessageRead { get; set; }

    public virtual Message Message { get; set; } = null!;
}
```

Жизненный цикл для получателя:

| Момент | Поле |
|--------|------|
| Сообщение создано, recipient записан | `MessageSent = UtcNow` |
| Сообщение попало в окно чата получателя (лента / realtime) | `MessageDelivered = UtcNow` (если ещё null) |
| Получатель прочитал (открытый хвост ленты / явный read) | `MessageRead = UtcNow` (если ещё null) |

Удаление сообщения — строки `Recipient` уходят вместе с `Message` (каскад / текущее поведение), отдельного `MessageDeleted` нет.

**Unread в списке чатов:** число сообщений чата, где у текущего пользователя есть recipient с `MessageRead == null` (отправитель в счётчик не входит — у него нет recipient или политика «только чужие»).

**Mark-read:** при открытии чата у низа ленты (или аналог) проставить `MessageRead` всем своим ещё не прочитанным recipient’ам в этом чате.

**Delivered:** клиент (или сервер при успешной доставке в группу `chat:{id}` открытого получателя) выставляет `MessageDelivered`; детали вызова — в реализации, без отдельного UI галочек в 0015, если не успеем — минимум для корректных полей.

### Превью

Усечённый текст последнего сообщения или ярлык вложения; время; имя отправителя при необходимости. Пустой чат — без превью.

### Сортировка

1. Есть last message → по `lastMessageAt` убыв.
2. Нет сообщений → новый чат выше (по времени создания чата / Id v7).
3. Realtime: при обновлении превью — переставить строку в UI.

### Realtime

- После create/update/delete, влияющего на last/unread: событие в `user:{id}` участников.
- Отправителю — превью без роста unread.
- После mark-read — сброс бейджа у читателя (локально + при необходимости событие себе).

### Вне объёма

Redis / `Caching`; SignalR backplane; UI галочек sent/delivered/read у пузырька (если не войдёт в реализацию — поля в БД всё равно заводим); typing (0016); «↓ новые» (0017); разделители дат (0018).
