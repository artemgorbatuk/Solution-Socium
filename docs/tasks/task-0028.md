**Описание:**

Выровнять членство в чате (заявка, добавление, выход, исключение, смена админа) с матрицей ролей [task-0021](task-0021.md): раздельные `can*`, UI только по разрешениям, единый realtime-контракт смены членства. Устраняет смешение Add/Kick/роли под один `canChangeRole` (= `ChatAdminGrant`).

**Функциональные требования:**

1. Матрица: роль → действие → UI → realtime — [Матрица членства](#матрица-членства).
2. Панель участников: «Сделать/снять админа» только при `canChangeAdmin`; поиск/Добавить и заявки — `canGrantParticipant`; «Выгнать» — `canKick` и не себе — [UI](#ui).
3. Topbar «Заявки»: видимость по семантике `ChatParticipantGrant`, не «просто isAdmin» — [UI](#ui).
4. После Kick/Leave исключённый сразу видит stub или теряет чат без F5 — [Realtime](#realtime).
5. Вне объёма: назначение `ChatAdmin` чистым `RoomAdmin` из UI комнаты; invite-токены; expiry заявок.

**Технические требования:**

1. `ParticipantListPageResponse`: `CanChangeAdmin`, `CanGrantParticipant`, `CanKick` вместо одного `CanChangeRole` — [API can](#api-can).
2. List считает флаги через `CanGrantAdminAsync` / `CanGrantParticipantAsync` / `CanRevokeParticipantAsync` — [API can](#api-can).
3. `participantLeft`: группа чата + `user:{leftUserId}` (как `joinRequestChanged`) — [Realtime](#realtime).
4. Chat-page: один обработчик потери членства; при потере `ChatRead` — обновление списка чатов комнаты — [Realtime](#realtime).
5. Тесты по персонам `RoomAdmin` / `ChatAdmin`+участник / обычный участник — [Персоны](#персоны).
6. Runbook `docs/runbook/realtime.md` — секция membership.

**Дополнительные сведения:**

### Матрица членства

| Действие | Разрешение / правило | Кто | UI | Realtime |
|----------|----------------------|-----|-----|----------|
| Видеть чат в комнате | `ChatRead` | `RoomAdmin`, `ChatAdmin`, `ChatParticipant` | список чатов | `chatChanged` |
| Лента / composer | `MessageRead` / `MessageCreate` | только `ChatParticipant` | `isParticipant` | — |
| Stub «Подать заявку» | `ChatRead` и нет `ChatParticipant` | типично `RoomAdmin` | stub chat-page | `joinRequestChanged` → заявитель |
| Accept / Reject / Add | `ChatParticipantGrant` | только `ChatAdmin` (+ `ChatParticipant` по инварианту) | заявки + поиск | `joinRequestChanged`, `participantJoined` |
| Выгнать | `ChatParticipantRevoke` | только `ChatAdmin` | «Выгнать» не себе | `participantLeft` → chat + user |
| Сделать/снять админа | `ChatAdminGrant` / `Revoke` | `RoomAdmin` или `ChatAdmin` | кнопки роли | `participantRoleChanged` |
| Покинуть | снятие своей роли | любой с `ChatParticipant` | «Покинуть чат» | `participantLeft` |
| Список участников | `ParticipantRead` | только `ChatParticipant` | панель | joined / left / roleChanged |

Инварианты: Kick снимает все `ChatRoleAssignments` цели; нельзя выгнать/уйти последнему админу; `ChatAdmin` только вместе с `ChatParticipant`.

### API can

`ParticipantListPageResponse`:

- `CanChangeAdmin` ← `CanGrantAdminAsync`
- `CanGrantParticipant` ← `CanGrantParticipantAsync`
- `CanKick` ← `CanRevokeParticipantAsync`

Info чата: `IsParticipant` / `IsAdmin` derived; topbar заявок — `CanManageParticipants` (= Grant) в info или тот же смысл через list/admin-флаг, явно не «сырой isAdmin» в комментариях UI.

### UI

Панель участников и панель заявок — см. ТР п. 2–3. Stub — `!isParticipant` при успешном info.

### Realtime

`NotifyParticipantLeftAsync`: `SendToChat` + `SendToUser(leftUserId)`. Клиент: у себя — `isParticipant=false`, leave hub-группы; если нет `ChatRead` — убрать чат из списка комнаты / reload.

### Персоны

1. `RoomAdmin` без `ChatParticipant`: stub заявки; нет Add/Kick/ленты.
2. `ChatAdmin`+`ChatParticipant`: Add, Kick, Accept, смена админа (если не последний).
3. Обычный `ChatParticipant`: Leave; нет Kick/Add.
4. Kick открытого чата у жертвы без F5.
5. Kick себя / последнего админа — 422.
