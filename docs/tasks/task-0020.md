**Описание:**

Create / rename / delete комнаты сразу отражаются в сайдбаре у всех подключённых клиентов (SignalR), без полной перезагрузки списка с сервера. Права доступа не меняем — [Решения разработчика](#решения-разработчика).

**Функциональные требования:**

1. Rename: сменили название — у остальных в дереве комнат сразу новое имя (и подписи вроде «Чаты комнаты …») — [Сценарий](#сценарий), [Frontend](#frontend).
2. Create: новая комната появляется в сайдбаре у всех онлайн — [Сценарий](#сценарий).
3. Delete: комната исчезает из сайдбара у всех онлайн — [Сценарий](#сценарий).
4. Без полного reload: клиент **патчит** локальный массив комнат (добавить / сменить name / убрать), не вызывает GET `/api/room` на каждое событие — [Frontend](#frontend).
5. Права: кто может create/update/delete — как сейчас; RBAC — [task-0021](task-0021.md).

**Технические требования:**

1. Аудитория: **все** подключённые к хабу (broadcast), не только участники чатов комнаты — [Realtime](#realtime).
2. Domain events **после** успешного `SaveChanges` в `ServiceRoom` (create / update / delete): одно событие с видом операции — [События](#события). Существующий `RoomCreated` **до** SaveChanges (авточат, [task-0019](task-0019.md)) не использовать для notify.
3. Handler тонкий → сервис/порт realtime notify; объекты события и payload — только через `{Entity}Mapper` в локальную переменную (rule-0003 п. 31, 44–45; [AGENTS.md](../../AGENTS.md)).
4. SignalR: клиентское событие `roomChanged`; на `IChatConnection` — `SendToAllAsync` — [Realtime](#realtime).
5. Frontend: подписка в сайдбаре; патч списка; инициатор без `loadRooms` после своего create/update/delete — [Frontend](#frontend).
6. Тесты: mapper; FE-патч create/rename/delete; ServiceRoom/RoomApi регрессия.
7. Документы: карточка; runbook realtime.

**Дополнительные сведения:**

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Кому слать | Всем подключённым к хабу (broadcast) |
| Объём | Create + rename + delete комнаты |
| Связка | Domain event после `SaveChanges` → handler → notify-сервис |
| Авточат 0019 | `RoomCreated` до SaveChanges без изменений; для UI — `RoomChangedEvent` после commit |
| Модель события | `RoomChangedEvent` с `RoomChangedKind` Created/Updated/Deleted |
| Создание объектов | Только Mapper → локальная переменная → вызов |
| FE | Патч локального списка, не GET всех комнат |
| Инициатор | Патч по `roomChanged` (create — expand по pending имени) |
| Права | Не менять; RBAC в task-0021 |

### Сценарий

1. Пользователь A создаёт / переименовывает / удаляет комнату.
2. После успешного commit в БД все онлайн-клиенты получают SignalR `roomChanged`.
3. Сайдбар патчит строку комнаты; полный список с API не запрашивается.

### События

```text
ServiceRoom.CreateAsync
  … Publish(RoomCreated)              // 0019 авточат, до Save
  await SaveChangesAsync()
  await Publish(RoomChanged Created)  // realtime UI

ServiceRoom.UpdateAsync / DeleteAsync
  …
  await SaveChangesAsync()
  await Publish(RoomChanged Updated|Deleted)
```

### Realtime

- `IChatConnection.SendToAllAsync` → `Clients.All`
- Клиентский метод `roomChanged`; payload: `kind`, `roomId`, `name?`

### Frontend

- Подписка в `Sidebar` на `roomChanged$`
- created / updated / deleted — патч `rooms` + сортировка по имени
- После своего create — `pendingExpandRoomName`, expand при событии
