**Описание:**

Добавить чаты (Chat): таблица `Chats` в БД Socium со связью «один ко многим» с комнатами — в комнате может быть много чатов, чат принадлежит ровно одной комнате. Сделать CRUD чатов на бекенде по образцу Room и показать чаты комнаты в боковой панели деревом.

**Функциональные требования:**

1. База данных: таблица `Chats`, каждый чат ссылается на свою комнату; при удалении комнаты её чаты удаляются вместе с ней — состав полей в [Состав полей Chat](#состав-полей-chat).
2. CRUD чатов: список чатов комнаты, карточка, создание, изменение названия и удаление через API `api/chat` плюс данные для форм — набор в [Эндпоинты API](#эндпоинты-api).
3. Перенос чата: не поддерживается — комната задаётся при создании, изменение меняет только название.
4. Названия: названия чатов не уникальны — в одной комнате могут быть чаты с одинаковым названием.
5. Дерево в боковой панели: комната раскрывается кнопкой ▸ / ▾, под ней — её чаты; по умолчанию комнаты раскрыты, свёрнутые запоминаются в браузере; создание, переименование и удаление чата — из меню — поведение в [Чаты в боковой панели](#чаты-в-боковой-панели).
6. Предупреждение: в окне удаления комнаты, у которой есть чаты, выводится их число («Вместе с комнатой будут удалены чаты: 3»).

**Технические требования:**

1. Структура: библиотеки, файлы, именование и слои — по [rule-0003](../rules/rule-0003-backend.md), по образцу цепочки Room (task-0003).
2. Связь: описана со стороны `Chat` — `HasOne(Room)` → `WithMany(Chats)`, `HasForeignKey(RoomId)`, `OnDelete(Cascade)`; индекс `IX_Chats_RoomId` (rule-0003, п. 12–13).
3. Миграция: одна миграция `Task0006`, накатывается при старте WebApi в окружении `Development`.
4. Выборка: все критерии выборки чатов — через `ChatQueryOptions` (`RoomId`); число чатов комнаты для окна удаления — метод репозитория `CountAsync(ChatQueryOptions)`, поле `ChatCount` в `RoomDeletePageResponse`.
5. Проверки чата: primary (запрос, пустые `Id` / `RoomId`) → accessibility (чат или комната найдены) → domain (название не пустое и не длиннее 128 символов).
6. Тесты: по [rule-0004](../rules/rule-0004-tests.md) — unit, интеграционные тесты сервиса и API, фронтенд-тесты и E2E; фикстуры интеграционных тестов — общие для area Socium.
7. Фронтенд: чаты — в `app/chats/` (клиент API, модели, список чатов комнаты, строка чата, окно удаления); стили — только токены rule-0005.

**Дополнительные сведения:**

### Состав полей Chat

| Поле   | Тип      | Обязательное | Ограничения                                                    |
|--------|----------|--------------|----------------------------------------------------------------|
| Id     | `Guid`   | Да           | Первичный ключ, `Guid` v7                                      |
| RoomId | `Guid`   | Да           | Внешний ключ на `Rooms.Id`, `ON DELETE CASCADE`, индекс `IX_Chats_RoomId` |
| Name   | `string` | Да           | `HasMaxLength(128)`, не уникально                              |

Навигация: `Chat.Room` и `Room.Chats`.

### Эндпоинты API

Набор по rule-0003 (п. 37), как у `RoomController`.

| Метод    | Маршрут            | Действие        | Метод сервиса            | Запрос / ответ                                     |
|----------|--------------------|-----------------|--------------------------|----------------------------------------------------|
| `GET`    | `/api/chat`        | `List`          | `DisplayListPageAsync`   | `ChatListPageRequest` (`roomId`) / `ChatListPageResponse` |
| `GET`    | `/api/chat/info`   | `Info`          | `DisplayInfoPageAsync`   | `ChatInfoPageRequest` / `ChatInfoPageResponse`     |
| `GET`    | `/api/chat/create` | `Create`        | `DisplayCreatePageAsync` | `ChatCreatePageRequest` (`roomId`) / `ChatCreatePageResponse` |
| `POST`   | `/api/chat`        | `Create`        | `CreateAsync`            | `ChatCreateRequest` (`roomId`, `name`) / `ChatCreatePageResponse` |
| `GET`    | `/api/chat/update` | `Update`        | `DisplayUpdatePageAsync` | `ChatUpdatePageRequest` / `ChatUpdatePageResponse` |
| `PUT`    | `/api/chat`        | `Update`        | `UpdateAsync`            | `ChatUpdateRequest` (`id`, `name`) / `ChatUpdatePageResponse` |
| `GET`    | `/api/chat/delete` | `DeleteConfirm` | `DisplayDeletePageAsync` | `ChatDeletePageRequest` / `ChatDeletePageResponse` |
| `DELETE` | `/api/chat`        | `Delete`        | `DeleteAsync`            | `ChatDeleteRequest` / `ChatDeleteResponse`         |

Список чатов комнаты сортируется по названию. Неизвестная комната в списке и при создании — `404`, пустой `roomId` — `400`.

### Чаты в боковой панели

| Блок             | Поведение                                                                                       |
|------------------|-------------------------------------------------------------------------------------------------|
| Раскрытие        | Кнопка ▸ / ▾ слева от названия комнаты (`aria-expanded`); по умолчанию все комнаты раскрыты; при каждом раскрытии чаты загружаются из `GET /api/chat?roomId=…` |
| Запоминание      | Id свёрнутых комнат хранятся в `localStorage` под ключом `socium.sidebar.collapsedRooms` (сервис `RoomExpansion`); после загрузки списка комнат удалённые комнаты из ключа убираются |
| Чаты             | Под комнатой с отступом; состояния «Загрузка…», «Чатов пока нет», ошибка загрузки               |
| Новый чат        | Пункт «Новый чат» в меню комнаты раскрывает комнату и открывает поле названия; «Создать» или Enter — `POST /api/chat`, Esc или «Отмена» — закрыть; ошибка сервера — под полем |
| Меню чата        | Кнопка «…» как у комнаты; пункты «Переименовать» и «Удалить»                                    |
| Переименование   | На месте строки, как у комнаты: `PUT /api/chat`; без изменений запрос не отправляется           |
| Удаление         | Окно подтверждения: название из `GET /api/chat/delete`, «Удалить» — `DELETE /api/chat`          |
| Удаление комнаты | В окне удаления комнаты при наличии чатов — «Вместе с комнатой будут удалены чаты: N»           |
