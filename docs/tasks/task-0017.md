**Описание:**

UX ленты сообщений: если пользователь ушёл вверх по истории, входящие realtime-сообщения не уводят скролл вниз сами — появляется индикатор «↓ новые»; по клику лента прыгает к хвосту. Сейчас любое `messageCreated` всегда скроллит вниз (`chat-messages`) — это мешает читать историю.

**Функциональные требования:**

1. У низа: пока лента у хвоста, новое сообщение (своё или чужое) по-прежнему дописывается и скролл остаётся у низа — [Поведение](#поведение).
2. Выше истории: если пользователь не у низа, чужое новое сообщение добавляется в ленту **без** автоскролла; показывается индикатор — [Индикатор](#индикатор).
3. Своя отправка: после успешной отправки своего сообщения лента всегда к хвосту, индикатор сбрасывается — [Поведение](#поведение).
4. Сброс индикатора: клик по индикатору → скролл к хвосту; либо пользователь сам долистал до низа — [Индикатор](#индикатор).
5. Счётчик: на индикаторе видно число непросмотренных новых сообщений с момента ухода вверх — [Индикатор](#индикатор).

**Технические требования:**

1. Только фронтенд (`chat-messages` + стили обеих тем); без API, миграций и изменений хаба — поверх realtime из [task-0014](task-0014.md).
2. Порог «у низа»: расстояние от низа ленты ≤ ~80–100 px — [Поведение](#поведение).
3. Логика: при `messageCreated` решать scroll vs badge по `isNearBottom`; update/delete не влияют на счётчик; подгрузка истории вверх не показывает индикатор — [Поведение](#поведение).
4. Тесты FE: у низа — скролл; выше — badge и счётчик; клик / доскролл — сброс.
5. Документы: при необходимости коротко в runbook или карточке; rule — только если появится общее правило UI ленты.

**Дополнительные сведения:**

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Backend / SignalR | Без изменений |
| Порог «у низа» | ≤ ~80–100 px до низа feed |
| Чужое сообщение не у низа | Без автоскролла + индикатор |
| Своё сообщение | Всегда скролл к хвосту, сброс badge |
| Текст | `↓ новые` при 1; `↓ N новых` при N ≥ 2 (или единый `↓ N новых` с N≥1 — на реализации, главное со счётчиком) |
| Клик | `scrollToEnd` + сброс счётчика |
| Доскролл руками к низу | Сброс счётчика |
| Update / delete | Не увеличивают счётчик |
| Load older | Не трогает badge |
| Reconnect `loadLatest` | Как сейчас — к хвосту; badge сбросить |

### As-is

В `chat-messages.ts` при `messageCreated` вызывается `upsertMessage(..., scrollIfNew: true)` → всегда `scrollToEnd()`. Нет проверки положения скролла.

### Поведение

1. **У низа** (`distanceToBottom ≤ threshold`): новое сообщение → append + `scrollToEnd`; badge скрыт / счётчик 0.
2. **Не у низа**: чужое новое → append без скролла; `unseenCount++`; показать индикатор.
3. **Своя отправка** (успешный create / echo своего `messageCreated`): `scrollToEnd`, `unseenCount = 0`, скрыть индикатор.
4. **Клик по индикатору** или **scroll до низа**: `scrollToEnd` (если клик), `unseenCount = 0`, скрыть.
5. Смена чата / destroy: сброс счётчика и индикатора.

### Индикатор

- Место: поверх низа ленты или между feed и composer (не перекрывать composer жёстко; кликабельная кнопка/chip).
- A11y: кнопка с понятным `aria-label` (например «Перейти к новым сообщениям»).
- Стили: через `--sc-*` токены, читаемо в светлой и тёмной теме; без отдельной «карточки»-декора, если достаточно кнопки.

### Вне объёма

Разделители дат ([task-0018](task-0018.md)); unread в списке чатов ([task-0015](task-0015.md)); звук/desktop-уведомления; «перейти к первому непрочитанному» внутри истории (только к хвосту).
