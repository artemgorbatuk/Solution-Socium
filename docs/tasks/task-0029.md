**Описание:**

Админ приложения (`AppAdmin`) видит список всех пользователей и их доступы на всех уровнях — приложение, комнаты, чаты — и управляет доступами других пользователей. Вход — иконка в топбаре слева от переключателя темы; список и доступы — страницы `/users` и `/users/:id`, обновляются без F5 при любом изменении ролей. Заодно удалённый пользователь теряет все роли. Опирается на RBAC [task-0021](task-0021.md) и членство [task-0028](task-0028.md).

**Функциональные требования:**

1. Иконка: в топбаре слева от переключателя темы иконка «Пользователи», видна только `AppAdmin` — [UI](#ui).
2. Список: страница `/users` — все пользователи (имя, логин, email, подтверждён ли email, пометка «админ приложения», пометка «удалён»), поиск по имени и логину, удалённые скрыты переключателем — [UI](#ui), [Удалённые пользователи](#удалённые-пользователи).
3. Карточка пользователя: страница `/users/:id` — переключатель «Админ приложения» и дерево всех комнат и чатов с переключателями ролей (`RoomAdmin` у комнаты; «Участник» / «Админ чата» у чата); включённые — текущие доступы, выключенные — доступные для выдачи; фильтр «Только с доступом» и поиск по названию — [Карточка пользователя](#карточка-пользователя).
4. Управление чужими доступами: включение переключателя выдаёт роль, выключение — снимает; `AppAdmin`, `RoomAdmin` в любой комнате, участник и админ в любом чате — [Управление](#управление).
5. Свои доступы: свою страницу `AppAdmin` только просматривает; исключение — может снять с себя `AppAdmin`, если он не последний — [Управление](#управление).
6. Хотя бы один админ везде: нельзя снять последнего `AppAdmin`, последнего `RoomAdmin` комнаты, последнего `ChatAdmin` чата — ни со страницы `/users`, ни выходом, ни исключением, ни удалением пользователя — [Инвариант «последний админ»](#инвариант-последний-админ).
7. Удаление пользователя: сообщения остаются с пометкой «удалён» у отправителя; все роли и членство снимаются автоматически; если пользователь — последний админ где-либо, удаление запрещено с перечнем мест — [Удалённые пользователи](#удалённые-пользователи).
8. Без F5: страницы `/users` и `/users/:id` у всех админов отражают любое изменение ролей — и со страницы доступов, и из чатов (добавление, исключение, выход, заявки, назначение админом, создание комнаты / чата), и регистрацию / удаление пользователей; у затронутого пользователя сразу обновляются сайдбар и открытый чат — [Realtime](#realtime).
9. Не-`AppAdmin`: иконки нет, `/users` недоступна, API отвечает `403`.

**Технические требования:**

1. Разрешения: `UserRead`, `UserAccessManage`, `AppAdminGrant`, `AppAdminRevoke` у `AppAdmin`; разрешения ролей чата `AppAdmin` не получает — [Разрешения](#разрешения).
2. Security API: список пользователей для админа с ролями приложения; выдача / снятие роли приложения — [API](#api).
3. Socium API: дерево «все комнаты → чаты» с текущими ролями пользователя и признаками блокировки переключателей; выдача / снятие ролей комнаты и чата по `UserAccessManage` — [API](#api).
4. Проверка прав — в сервисе (`ValidateAccess*`); Socium узнаёт роли приложения через `IUserRolePort` (rule-0003 п. 41); запрет правки своих доступов — валидация «цель ≠ текущий пользователь».
5. Роли чата меняются через `ServiceParticipant` (stage-методы) — инварианты не дублируются (rule-0003 п. 45); проверка «последний админ» — один валидатор на уровень, вызывается из всех сценариев.
6. Удаление пользователя: Security публикует `UserDeletedEvent`; снятие ролей в Socium — через порт и адаптер в WebApi; проверка «последний админ» — до `SaveChanges` удаления — [Удалённые пользователи](#удалённые-пользователи).
7. Флаг `canManageUsers` в профиле аккаунта — только для показа иконки и guard; сервер проверяет права на каждый запрос (task-0021, «Права в токене») — [UI](#ui).
8. Realtime: событие `userAccessChanged` после любого изменения назначений ролей или списка пользователей — [Realtime](#realtime).
9. Тесты: unit `RoleCatalog` и валидаторов; интеграционные API по персонам (`AppAdmin`, второй `AppAdmin`, обычный пользователь); последний админ на трёх уровнях; удаление пользователя; FE — иконка, guard, страницы, realtime.

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Что такое «доступы» | Роли всех уровней: приложение (`AppAdmin`), комнаты (`RoomAdmin`), чаты (`ChatAdmin` / `ChatParticipant`) с названиями комнат и чатов |
| Просмотр или управление | Просмотр и управление ролями всех уровней |
| Где показывать | Отдельная страница `/users` со списком; доступы пользователя — `/users/:id` |
| Где иконка | Топбар, слева от переключателя темы |
| Свои доступы | `AppAdmin` свои доступы не редактирует; их меняют другие `AppAdmin` |
| Снятие `AppAdmin` с себя | Можно, если он не последний `AppAdmin` |
| Последний админ | Всегда хотя бы один админ на каждом уровне: приложение, комната, чат |
| Права `AppAdmin` в чатах | Не расширяются: управление ролями чата — отдельным разрешением `UserAccessManage` только через `/users`; себе выдать участника нельзя, значит чужие чаты он не читает |
| Удалённый пользователь | Мягкое удаление сохраняется; сообщения остаются с пометкой «удалён»; все роли снимаются автоматически; последнего админа удалить нельзя |
| Вид карточки пользователя | Дерево всех комнат и чатов с переключателями ролей: сразу видно, что есть и что можно выдать; без отдельной формы «Добавить доступ» |
| Закладки | Не нужны: одна страница с деревом; обратный вид «комната → у кого доступ» — отдельной задачей при необходимости |
| Обновление страниц | Любое изменение ролей где-либо отражается на `/users` и `/users/:id` без F5 |

### Разрешения

Новые поля `PermissionNames` (формат `{Сущность}.{Операция}`):

| Поле | Значение | Что даёт |
|------|----------|----------|
| `UserRead` | `User.Read` | Видеть список пользователей и их доступы |
| `UserAccessManage` | `UserAccess.Manage` | Выдавать и снимать роли комнат и чатов другим пользователям со страницы `/users` |
| `AppAdminGrant` | `AppAdmin.Grant` | Выдать пользователю роль админа приложения |
| `AppAdminRevoke` | `AppAdmin.Revoke` | Снять роль админа приложения |

Выдачи `AppAdmin` (`RoleScope.App`) после задачи: `RoomCreate`, `RoomRead`, `RoomAdminGrant`, `RoomAdminRevoke` (уже есть) + `UserRead`, `UserAccessManage`, `AppAdminGrant`, `AppAdminRevoke`. `ChatParticipantGrant` / `ChatAdminGrant` и т.п. `AppAdmin` **не** получает: `ParticipantPolicy` и API участников (`/api/participant`) для него не меняются.

### API

| Область | Метод | Путь | Сервис | Модели |
|---------|-------|------|--------|--------|
| Security | `GET` | `/api/user/admin` | `IServiceUser.DisplayAdminListPageAsync` | `UserAdminListPageRequest` (`IncludeDeleted`) / `UserAdminListPageResponse` (`Rows`: `Id`, `Login`, `Name`, `Email`, `IsEmailConfirmed`, `IsDeleted`, `IsAppAdmin`, `CanGrantAppAdmin`, `CanRevokeAppAdmin`) |
| Security | `POST` | `/api/appRole` | `IServiceAppRole.CreateAsync` | `AppRoleCreateRequest` (`UserId`, `RoleName`) |
| Security | `DELETE` | `/api/appRole?userId=&roleName=` | `IServiceAppRole.DeleteAsync` | `AppRoleDeleteRequest` |
| Socium | `GET` | `/api/roleAssignment?userId=` | `IServiceRoleAssignment.DisplayListPageAsync` | `RoleAssignmentListPageResponse` — дерево, см. ниже |
| Socium | `POST` | `/api/roleAssignment` | `IServiceRoleAssignment.CreateAsync` | `RoleAssignmentCreateRequest` (`UserId`, `RoleName`, `RoomId?`, `ChatId?`) |
| Socium | `DELETE` | `/api/roleAssignment?userId=&roleName=&roomId=&chatId=` | `IServiceRoleAssignment.DeleteAsync` | `RoleAssignmentDeleteRequest` |

`RoleAssignmentListPageResponse` — все комнаты (сортировка по названию), в каждой все её чаты; на узле — текущие роли пользователя и признаки для блокировки переключателей:

| Узел | Поля |
|------|------|
| Корень | `UserId`, `CanManage` (= `UserAccessManage` и цель ≠ текущий, цель не удалена), `Rooms` |
| Комната | `RoomId`, `RoomName`, `IsRoomAdmin`, `IsLastRoomAdmin`, `Chats` |
| Чат | `ChatId`, `ChatName`, `IsParticipant`, `IsChatAdmin`, `IsLastChatAdmin` |

Дерево строится одним запросом на назначения пользователя и одним — на число админов по комнатам и чатам (без SQL на каждый узел, ТТ17 [task-0021](task-0021.md)). Фильтр «Только с доступом» и поиск — на клиенте.

Существующий `GET /api/user` (имена для порта, любой вошедший) не меняется. Названия сервисов и путей уточняются при реализации по rule-0003.

### Управление

Каждый переключатель карточки — один запрос `POST` (включить) или `DELETE` (выключить):

| Переключатель | Включить | Выключить | Разрешение | Реализация | Ограничения |
|---------------|----------|-----------|------------|------------|-------------|
| «Админ приложения» | Выдать `AppAdmin` | Снять `AppAdmin` | `AppAdminGrant` / `AppAdminRevoke` | `AppRoleAssignments` (Security) | Включить — не себе; выключить у себя — можно; последнего — нельзя |
| «Админ комнаты» | Назначить `RoomAdmin` | Снять `RoomAdmin` | `UserAccessManage` | `ServiceRoom.AssignRoomAdminStageAsync` + новый revoke stage | Не себе; последнего — нельзя |
| «Участник» чата | Добавить участником | Исключить: снять все роли чата + `Participants` (как Kick) | `UserAccessManage` | `ServiceParticipant.CreateStageAsync` / снятие как Kick | Не себе; уже участник — `422`; исключить последнего `ChatAdmin` — нельзя |
| «Админ чата» | Сделать админом | Снять админа | `UserAccessManage` | Как смена роли в `ServiceParticipant` | Не себе; только при включённом «Участник»; последнего — нельзя |

### Инвариант «последний админ»

Один валидатор на уровень (`ValidateDomainLastAppAdmin`, `ValidateDomainLastRoomAdmin`, `ValidateDomainLastChatAdmin`), вызывается во всех сценариях, где роль админа может пропасть:

| Уровень | Сценарии |
|---------|----------|
| Приложение | Снятие `AppAdmin` (своё и чужое); удаление пользователя |
| Комната | Снятие `RoomAdmin` со страницы `/users`; удаление пользователя |
| Чат | Снятие админа, Kick, Leave (уже есть — [task-0028](task-0028.md)); страница `/users`; удаление пользователя |

Ответ — `422` с текстом, где пользователь последний админ.

### Удалённые пользователи

1. Удаление остаётся мягким (`Users.IsDeleted`), вход и refresh-токены отзываются как сейчас; сообщения и вложения не удаляются — история чатов не рвётся.
2. Перед удалением Security через порт спрашивает Socium, где пользователь последний `RoomAdmin` / `ChatAdmin`, и сам проверяет последнего `AppAdmin`; если где-то последний — `422` с перечнем, пользователь не удаляется.
3. После `SaveChanges` удаления публикуется `UserDeletedEvent`; handler через порт → WebApi → Socium снимает все `RoomRoleAssignments`, `ChatRoleAssignments`, строки `Participants` и pending-заявки; Security снимает `AppRoleAssignments`; затем notify `participantLeft` / `userAccessChanged`.
4. Отправитель удалённого — имя с пометкой «(удалён)» в ленте; в `/users` — строка с пометкой «удалён», без действий; по умолчанию скрыта (переключатель «Показать удалённых»).
5. Удаление чужого пользователя админом — вне задачи (сейчас удаляет только сам себя).

### Карточка пользователя

```text
← Пользователи
Анна Петрова  @anna  anna@example.com

Приложение:  [✓] Админ приложения

Поиск: [__________]        [✓] Только с доступом
▾ Тест 1                   [✓] Админ комнаты
    # Чат 1                [✓] Участник   [✓] Админ чата
    # Чат 2                [ ] Участник   [ ] Админ чата
▸ Тест 2                   [ ] Админ комнаты
```

1. Шапка: имя, логин, email; ссылка «← Пользователи».
2. «Приложение»: один переключатель «Админ приложения».
3. Дерево: комната — строка с переключателем «Админ комнаты», под ней её чаты с переключателями «Участник» и «Админ чата». Комнаты сворачиваются; по умолчанию раскрыты.
4. Фильтр «Только с доступом» (по умолчанию включён): показываются комнаты, где у пользователя есть роль комнаты или роль хотя бы в одном её чате, и только такие чаты. Выключен — все комнаты и чаты, то есть всё, что можно выдать.
5. Поиск по названию комнаты или чата: комната остаётся в выдаче, если совпало её название или название одного из чатов.
6. Переключатель неактивен (с подсказкой `title`, почему):
   - своя карточка — все, кроме выключения своего «Админ приложения»;
   - удалённый пользователь — все;
   - последний админ комнаты / чата / приложения — выключение;
   - «Админ чата» — пока выключен «Участник».
7. Выключение «Участник» у админа чата снимает обе роли — перед этим подтверждение на месте: «Исключить из чата «…»? Роль админа тоже будет снята».
8. Во время запроса — переключатель неактивен; ошибка сервера (например `422` «последний админ») — текстом под строкой, переключатель возвращается в прежнее положение.
9. После успешного запроса дерево перечитывается (`GET`), а не патчится вручную: меняются признаки «последний админ» у соседних строк.

| `userAccessChanged` (`userId`) | Все подключения (broadcast, как `userChanged`) | Любое изменение назначений ролей: `/users`, Add / Kick / Leave, Accept заявки, смена админа чата, создание комнаты / чата, `AppAdmin` grant / revoke; регистрация и удаление пользователя | `/users` — перечитать список; `/users/:id` — перечитать дерево при любом `userId` (чужое изменение может сделать этого пользователя последним админом), с объединением частых событий; если `userId` — я: перечитать комнаты и чаты в сайдбаре и профиль (`canManageUsers`) |
| `participantJoined` / `participantLeft` / `participantRoleChanged` | Как в [task-0028](task-0028.md) | Без изменений | Без изменений |

Payload — только `userId`, без ролей: данные читаются REST с проверкой `UserRead`.
