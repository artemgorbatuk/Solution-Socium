**Описание:**

Добавить проект тестов бекенда и покрыть тестами сначала базовый контур, от которого зависят все сущности (тестовая БД, модель ответа, перевод `MessageType` в HTTP), а затем CRUD комнат. Устройство тестов закрепить правилом по образцу эталона `autoclass-reports.ru`, с улучшениями. После появления боковой панели (task-0003) — дополнить негативные сценарии изменения и удаления, добавить сквозные (E2E) тесты комнат через UI и описать в правиле тесты фронтенда и E2E.

**Функциональные требования:**

1. Запуск: `dotnet test` из `src/backend/SociumApp/` запускает все тесты бекенда — одной командой, без ручной подготовки, кроме запущенного локального PostgreSQL.
2. Базовые тесты: проверены тестовая инфраструктура БД, фабрики `ResponseInfo` и перевод `MessageType` в HTTP-ответ в `ApiControllerBase` — список в [Состав тестов](#состав-тестов).
3. Тесты Room: проверены валидаторы, нормализатор и маппер, сервис с реальной БД и все восемь эндпоинтов API с кодами ответов — список в [Состав тестов](#состав-тестов).
4. Изменение и удаление: для страниц и операций изменения и удаления проверены пустой `Id` (`400`), неизвестная комната (`404`), слишком длинное и занятое название (`422`) — и в сервисе, и через HTTP.
5. E2E комнат: в настоящем UI боковой панели поверх настоящих WebApi и БД проверены сценарии «создать → переименовать → удалить», переименование в занятое название с ошибкой сервера и отмена удаления.
6. Правило: в rule-0004 описаны тесты фронтенда (Vitest) и E2E (Playwright).

**Технические требования:**

1. Правило: устройство тестов — по [rule-0004](../rules/rule-0004-tests.md); отличия от эталона — в [Отличия от эталона](#отличия-от-эталона).
2. Стек: xUnit v3 (`xunit.v3.mtp-v2`) на Microsoft Testing Platform, `Microsoft.AspNetCore.Mvc.Testing` для API; раннер задан в `global.json` в корне репозитория.
3. Расположение: проект `src/backend/SociumApp/Tests/Tests.csproj`, добавлен в `Solution-Socium.slnx`.
4. БД в тестах: временная БД на локальном сервере `socium-dev-postgres` (`localhost:5433`) на каждую фикстуру, удаляется после тестов; рабочая БД `Socium` не затрагивается.
5. Без лишнего: Testcontainers и Moq не подключаются — для текущего объёма они не нужны. Playwright подключён, когда у комнат появился экран (ТТ 6).
6. E2E: Playwright для .NET (`Microsoft.Playwright` 1.62.0) в проекте `Tests`; фикстура поднимает временную БД, WebApi отдельным процессом в окружении `Development`, сборку фронтенда во временную папку и статический сервер `scripts/e2e/serve-frontend-static.mjs` с прокси `/api` на свободных портах; Chromium ставится автоматически при первом запуске; E2E помечены `[Trait("Category", "E2E")]`.

### Отличия от эталона

| Тема                       | Эталон (`rule-0008`, `Tests/`)                                        | Socium (`rule-0004`)                                                  |
|----------------------------|-----------------------------------------------------------------------|-----------------------------------------------------------------------|
| Недоступный PostgreSQL     | Запасной вариант — Testcontainers с отключённым Ryuk                  | Тест падает сразу с подсказкой, как запустить compose (п. 10)         |
| Шаблон подключения         | `TEST_POSTGRES` / `ConnectionStrings__Reports`, порт `5432`           | `TEST_POSTGRES` / `ConnectionStrings__Socium`, порт `5433` (п. 9)     |
| Окружение API-тестов       | `AddDbContextExt` пропускает регистрацию в `Testing`, фикстура регистрирует контекст заново | Строка подключения подменяется конфигурацией, регистрация одна (п. 14) |
| Именование и состав        | Не описаны                                                            | Один шаблон имени для всех слоёв со словарём условий, минимальный набор для CRUD-сущности (п. 5, 6) |
| Изоляция и проверки        | Не описаны                                                            | Уникальные данные на тест, проверки по `MessageType` и `*Texts` (п. 13, 15) |
| Общий контур               | Тестов `ResponseInfo` и `FromResponse` нет                            | Обязательны при изменении контура (п. 7)                              |
| Прокси `/api` в E2E        | Префикс `/api` срезается                                              | Путь сохраняется — маршруты WebApi `api/[controller]` (п. 24)         |
| Chromium для E2E           | Ставится вручную через `playwright.ps1` (нужен PowerShell 7)          | Ставится фикстурой автоматически при первом запуске (п. 26)           |
| Сборка фронтенда для E2E   | В общую папку `dist`                                                  | Во временную папку, удаляется после прогона (п. 24, 25)               |
| Отбор E2E                  | Только по классу                                                      | Признак `Category=E2E` — можно исключить из быстрого прогона (п. 23)  |
| Тесты фронтенда в правиле  | Не описаны                                                            | Стек, HTTP, поиск элементов, глобальное состояние (п. 18–22)          |
