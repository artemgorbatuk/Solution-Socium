**Описание:**

При создании комнаты автоматически создаётся пустой чат «Новый чат»; создатель становится его участником и админом (`Participant.IsAdmin`). Сценарий связывается через in-process domain event `RoomCreated`, без вызова `IServiceChat` из `ServiceRoom` (rule-0003 п. 26).

**Функциональные требования:**

1. Авточат: после успешного создания комнаты в ней есть чат с именем «Новый чат» без сообщений — [Сценарий](#сценарий).
2. Админ: создатель комнаты (текущий пользователь) — участник этого чата с `IsAdmin = true` — [Сценарий](#сценарий).
3. Атомарность: комната, чат и участие либо все в БД, либо ничего — [События и транзакция](#события-и-транзакция).
4. Ручное создание чата: кнопка «Новый чат» в сайдбаре по-прежнему через `ServiceChat` — без изменений контракта.
5. UI: после создания комната в сайдбаре **раскрыта** (чат «Новый чат» виден в дереве) — [Решения разработчика](#решения-разработчика).
6. Только новые комнаты: существующие пустые не донаполняются — [Решения разработчика](#решения-разработчика).

**Технические требования:**

1. Шина событий: `IDomainEvent`, `IDomainEventHandler<T>`, `IDomainEventPublisher` / `DomainEventPublisher` — в `Services.Shared/Events/`; оформление файлов — [AGENTS.md](../../AGENTS.md) — [Состав классов](#состав-классов).
2. Событие Socium: `RoomCreatedEvent` + handlers в одном файле `Services.Socium/Events/RoomCreatedEvent.cs` — [AGENTS.md](../../AGENTS.md).
3. Порядок: `Rooms.CreateAsync` → `await Publish(RoomCreated)` (sync handlers) → один `SaveChangesAsync` в `ServiceRoom.Create` — [События и транзакция](#события-и-транзакция).
4. Id комнаты: после `CreateAsync` (генератор Guid v7 при Add), до SaveChanges — его можно передать в событие и в `Chat.RoomId`.
5. Handler: тонкий — вызывает `IServiceChat.CreateStageAsync` (без `SaveChanges`); логика создания — в сервисе чата (rule-0003 п. 44–45).
6. Create комнаты: нужен текущий пользователь (иначе нельзя назначить админа) — при отсутствии `401`, как у create чата.
7. Документы: карточка; правила агента уже в `AGENTS.md`; при необходимости коротко в rule-0003 (исключение/события).
8. Тесты: создание комнаты → чат «Новый чат» + админ; откат при ошибке; ручной create чата не ломается.

**Дополнительные сведения:**

### Решения разработчика

| Вопрос | Решение |
|--------|---------|
| Связка комната → чат | Domain event `RoomCreated` → handler → `IServiceChat.CreateStageAsync` (логика в сервисе) |
| Транзакция | Один `SaveChanges` после `await Publish`; Stage без commit |
| Publish | Синхронный `await` всех handlers до SaveChanges (не fire-and-forget) |
| Имя чата | `ChatCrudTexts.Defaults.Name` («Новый чат») |
| Шина | `Services.Shared/Events/` |
| Событие + handlers | Один файл `Services.Socium/Events/RoomCreatedEvent.cs` |
| Интерфейс + реализация | Один файл без `I` в имени; интерфейс сверху, реализация ниже (`AGENTS.md`) |
| UI после create | Комната раскрыта в сайдбаре (чат виден); открывать чат по URL не обязательно |
| Старые пустые комнаты | Не донаполнять; при необходимости удалит разработчик вручную |
| Ответ API create комнаты | `roomId` / `chatId` не добавлять, пока нигде не потребуются (раскрытие — по имени после reload списка) |

### Сценарий

1. Пользователь создаёт комнату (вошедший).
2. В БД появляются: Room, Chat («Новый чат»), Participant (создатель, админ).
3. При ошибке на любом шаге до/на SaveChanges — в БД нет ни комнаты, ни чата.
4. В UI список комнат обновляется, новая комната раскрыта.

### События и транзакция

```text
ServiceRoom.CreateAsync
  Rooms.CreateAsync(room)                 // Id уже есть
  await Publish(RoomCreatedEvent)         // handler → Chat.CreateStageAsync (UoW, без Save)
  await SaveChangesAsync()                // один commit
```

### As-is

- `ServiceRoom.Create` пишет только Room, текущего пользователя не использует.
- Админ есть только у чата (`Participant.IsAdmin`); создатель комнаты админом комнаты не становится (сущности «админ комнаты» нет).
- Ручной чат: `ServiceChat.Create` + участник-админ.
